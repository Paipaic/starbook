# Starbook 照片批量导入

用户提供素材目录并要求导入 Starbook 时使用。先检查当前项目版本和线上编辑器，依据 `references/starbook.md` 选择可用路径。默认目标是 https://paipaic.github.io/starbook ，使用用户自己的登录会话；登录配置见 `references/ui-workflow.md`，不得索取或输出密码、令牌，也不得使用特权密钥。不要修改原始照片和故事，清单放在用户指定的可写工作目录。

## 处理素材

1. 运行 `python scripts/prepare.py scan <素材目录> --output <工作目录>/manifest.json`；素材可以是 `<城市>/<日期_主题>/照片和故事.md`，也可有照片子目录或已经整理过的文案。扫描仅建立清单，不代表文案已生成或可上传。检查扫描遗漏、识别失败和媒体清单；旧绝对路径和旧 JSON 不作为事实来源。
2. 对每个事件读取 `故事.md` 并逐张实际查看照片，执行 [固定创作与设置 prompt](references/creative-prompt.md)。辨认画面和故事的对应关系；以故事中的事实为准，不推测身份、时间、地点或事件。用自然、朴素而有感情的第一人称写标题、导入语、照片与分组描述，允许有克制的创作性情感表达，不编造事实或他人心理。
3. 将相近场景、同一时刻或相关叙事的照片编为组，保留有意义的叙事顺序；不同主题不强行合并。单张可不分组。组描述写共同故事；单张描述仍可保留，但网页放映组内不显示单张描述。按组调整清单中照片顺序，确保每组连续。选择合适封面。已有放映文案可以作为参考，但用户明确要求新生成时，必须自行看图和读故事，不能把旧文案或旧状态当作已审核。
4. 补全清单：国家、网页使用的省/州名称、城市、源日期及网页年月、标题、导入语、照片描述、分组、封面、放映风格、季节、音乐模式和各项选择理由。按创作 prompt 自主选择，季节目前统一 `auto`（按月份），用户后续指定优先。城市或行政区有歧义时核实；未知城市不要猜。年月无法可靠确定时不能默认为当前日期；节日日期可查证年份后转换，并记录来源。没有可确定时间或地点的照片跳过上传：若整段事件的时间或地点不确定，跳过整个事件；若仅部分照片与该事件的时间或地点无法对应，跳过这些照片。记录原因，继续处理其余可确认素材。`待确认城市` 下的素材在确认前不上传。视频一律不上传，仅记录和保留原文件。对无法识别、失配、冲突或不支持的文件列出问题。
5. 将跳过的事件和照片及原因记入独立报告，从待上传清单中移除；保留原始扫描清单以供追溯。运行 `python scripts/prepare.py validate <待上传清单.json>`，解决待上传部分的错误；不要因程序通过而跳过看图、文案质量和地点核实。保留原日期精度、文件映射和哈希以供核对。如果没有可上传事件，报告结果并结束。

## 导入与核验

先读 [网页操作与控件](references/ui-workflow.md)，并核对线上版本和实际页面；按钮依据 v1.9.2 项目代码整理，已对一段真实回忆验证上传、分组和重开，城市创建与失败处理仍需核实。使用当前网页正常的城市添加、照片上传、编辑保存流程，选择正确国家及省/州，复用已有城市。先检查当前 Book 与编辑权限和现有回忆；可疑重复项先核对，不能覆盖或重复创建。仅上传时间和地点已确定的照片，不上传视频；跳过不确定的素材后重新核对封面和分组，若事件不剩照片则跳过该事件。逐事件上传照片、等待上传成功、设置标题、年月、导入语、顺序、封面、分组和组描述后保存；重开检查文字、照片数量、顺序及分组。记录成功、失败、跳过和未知结果及对应事件；保存结果不确定时先核实，禁止盲目重试。不可用或登录受阻时停下并说明，不绕过权限。不得清空、重置或批量覆盖已有 Book。

网页如增加正式批量导入入口，验证其支持分组及图片并优先采用；不要假设旧 importer 存在，也不要直接覆写 `book_data`。仅在环境提供合适的浏览器文件上传能力时操作；遇到无法选取本地文件的限制如实报告。用户只要求整理时不上传；用户明确要求导入时，上传是任务的一部分。用户已整理的素材或文案未经明确许可不覆写。

`references/starbook.md` 记录基于 v1.9.2 代码的具体限制，实际操作前核对是否仍适用。扫描工具只检查结构和基本字段；不会识别画面、生成文案、上传或证明地点正确。
