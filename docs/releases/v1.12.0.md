# Starbook v1.12.0 — 数据安全：最近删除 · 导出整本书

## 1. 版本目标

规划文档（仓库外 `星屿之书-后续迭代规划.md`）#1 回收站、#2 导出整本书。背景（2026-11-02 Owner 确认）：Supabase 为 **Free 套餐，没有自动备份**；即使付费套餐的数据库备份也不含 Storage 照片。v1.11.1 及以前，删除回忆 / 城市、在编辑器移除照片、替换音乐，保存成功后会**立即永久删除** Storage 文件。

次版本号 1.12.0（新功能 + 数据策略变化：软删除；无 schema 变化）。

## 2. 用户可见变化

- 右上角新增「珍藏与备份」标识（在动效与账户之间）。
- 「最近删除」（编辑者）：删除的城市（连同回忆）、回忆、照片保留 30 天；可恢复、彻底删除、清空；显示还剩几天；替换掉的音乐等文件只显示数量。
- 「导出整本书」（所有成员）：book.json + 原图 + 音乐 + 最近删除的内容打包成 zip；进度、取消、失败重试与清单；电脑 400 MB / 手机 150 MB 分卷，第 2 卷起点按钮保存；面板显示上次导出日期。
- 删除确认文案改为「移到最近删除，30 天内可以恢复」。

## 3. Runtime 链路变化

- `SB.store.mutate()`：写入前把「不再被引用的文件」记入 `trash.files`；仅 `purge` 模式删除 Storage 文件。`refs()` 含回收站媒体。编辑者载入后 4 秒静默清理超过 30 天的回收站条目。
- 新块 `blocks/16-archive.html`（`SB.archive`），通过 `SB.dock` 注册；JSZip 只在导出时按需加载。
- Scene Runtime / Gate：无变化。

## 4. 架构 / 扩展契约变化

新增 Store 接口与导出格式 `starbook-export` v1（见 `docs/ARCHITECTURE_EXTENSION_CONTRACT.md` v1.12.0 节）。回收站与导出以 Book 为单位，不涉及账户 / 成员，不绑定关系类型或 Theme。`SB.book` / `SB.magicBook` / `SB.store` 职责不变。

## 5. Auth / Membership / RLS 变化

无变化。导出使用现有成员的 Storage 读取权限（`download`）；回收站操作只对编辑者开放（与原删除权限一致）。

## 6. 数据模型 / Migration 变化

无 schema 变化、无 SQL。新增可选字段 `book_data.payload.trash = {memories, cities, photos, files}`；旧数据无需迁移。数据策略变化已写入 `docs/DATA_LIFECYCLE.md` v1.12.0 节。

## 7. Storage / Media 变化

Storage 内容与权限无变化。行为变化：删除后的文件在回收站期间保留（最长 30 天），彻底删除 / 清空 / 过期清理时才删除。

## 8. Git / Branch / PR / Merge 链路变化

无变化：`release/v1.12.0 → PR → validate-starbook → squash main → GitHub Pages`，Owner 使用 `ship-starbook.ps1`。

## 9. CI / Validation 变化

## 17. Production 数据影响

- 是否需要重新导入旧数据？**否。**
- 是否需要运行 SQL？**否。**
- 是否会删除/覆盖现有数据？**否。** 本版只会让删除变得「可撤销」；新增的 `trash` 字段在下一次保存时写入。

## 18. 已知问题

- 旧版本（未刷新的标签页）保存时会丢掉 `trash` 字段：回收站里的条目从界面消失（文件不会被删除，成为孤立文件）。发布后请刷新所有设备。
- 导出在手机上受内存限制，照片很多时请在电脑上导出；JSZip 默认把每卷的全部文件放在内存里，已用分卷控制。
- 还没有「从导出包恢复」的工具（DATA-003）。
- 回收站数据存在 `book_data.payload` 内，会让每次保存的数据稍大（30 天后自动清理）。

## 19. 回滚方案

revert v1.12.0 merge commit 即恢复 v1.11.1；回滚后回收站条目在下一次保存时被旧前端丢弃（文件保留为孤立文件，不影响功能）。数据无需回滚。
