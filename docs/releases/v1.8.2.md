# Starbook v1.8.2 — 回到魔法书 · 星尘启封 · 手机性能修复

## 1. 版本目标

Owner iPhone 真机反馈（v1.8.1）：
1. 新增回到魔法书首页的按钮（不放在左上菜单列表里）；
2. 光点汇聚落下仍然曝光严重——重新设计开书特效；
3. 手机非常卡：首页加载慢、魔法书动态几乎看不到并一直闪烁、上方有刺眼大光球、开书动画看不见直接卡几秒跳到星图。

定位过程与设计见 `docs/design/VISUAL_UPGRADE_PLAN.md` 第 11 节。

## 2. 用户可见变化

- 右上角标识组最左侧新增「书本」标识：任意页面一键回到魔法书封面（魔法书页面上自动隐藏）。
- 开书特效「星尘启封」：宝石柔和唤醒 + 一圈细光环 → 封面打开、纸页翻动 → 扉页上金墨自己画出星图，星尘从书页四周向上飘散 → 推进书页 → 暮色光门。无汇聚、无闪白。
- 手机上魔法书不再闪烁 / 对角切割，没有大光球，动效流畅；第二次打开网站明显更快；开书动画完整可见。

## 3. Runtime 链路变化

- `04-book-opening`：移除开书期间的 `SB.scenes.prefetch('globe')`；地球 WebGL 初始化在门钥匙 cover 完成后的 `prepareTarget` 中进行（Scene Runtime 事务不变）。不再调用 `SB.fx.gather / warp / burst`、`fxSuck`；新增 `SB.magicBook.fxOpen(on)`。
- `03-magic-book`：符文环改为 2D 投影的 `#bk-runes-back` / `#bk-runes-front`；薄烟正常混合、仅 high；新增扉页星图 `#bk-const`；low 档廉价烫金滤镜、关闭昂贵层；纹理缓存（localStorage）。
- `11-memory-player`：颗粒 / 墨滴纹理延迟到 `prime()` / `prepare()` 首次调用时生成。
- `02y-dock`：支持 action 类标识（无面板），新增 `home`。

## 16. 测试与验证

- `python build.py` + `python tools/check_project.py` → OK（21 blocks、0 语法错误、0 重复 id）。
- 手机仿真（390×844、4× CPU 降速、CDP 采样）：
  - 修改前：开书后出现 6.3s 与 17.6s 的长任务（WebGL 创建 + 着色器编译），开书期间几乎 1 fps；启动时皮革纹理约 1.4s、放映器纹理约 0.7s（未降速）。
  - 修改后：开书期间不再有 WebGL 长任务（只剩门钥匙盖满后的地球准备）；缓存命中后启动不再生成纹理；开书前 3.3 秒主线程任务时间从约 708ms/s 降到约 135ms/s。
- 开书慢动作逐帧（电脑华丽档、手机柔和档）：无白斑、无闪白，扉页星图正常描出。
- 全链路（high / low）：魔法书 → 地球 → 国家 → 城市 → 放映 → 返回 ×3 → 「回到魔法书」→ 地球 → 时光长卷 → 放映 → 返回；无错误、无残留遮罩。
- 手机 390px 顶栏：左上按钮 + 返回光球 + 四枚标识不重叠。

## 18. 已知问题

- 门钥匙盖满画面后，地球在低端手机上首次准备可能需要 1–2 秒，期间暮色光门画面静止（这是有意为之：卡顿被遮在门后，而不是冻结开书动画）。第二次进入地球即时。
- 测试环境没有真实 GPU，渲染帧率以真机为准。
