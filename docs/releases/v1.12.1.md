# Starbook v1.12.1 — 从备份导入（与导出格式对应）

## 1. 版本目标

Owner 需求（2026-11-03，基于 v1.12.0）：补充「重新导入」功能；导出功能的文件及格式要与导入对应，照片、地点、时间、编组等各项设置关系都要对应上。

修订号 1.12.1（新功能，数据只加不删，无 schema 变化）。原计划的 v1.12.1 体验项（真实坐标、省份中文名、忘记密码）顺延为 v1.12.2。

## 2. 用户可见变化

- 「珍藏与备份」新增「从备份导入」（编辑者）：多选 zip → 校验 → 预览（新增 / 已存在 / 文件是否齐全 / 是否来自另一本书）→ 可选「用备份覆盖已有的回忆和城市」→ 上传缺少的照片 → 合并 → 结果与缺失清单。
- 导出的每一卷新增 `part.json`，README 新增「重新导入」说明。

## 3. Runtime 链路变化

- `SB.store`：`bookId / mediaExists / putPath / importBackup`。导入先上传媒体、最后一次 `mutate` 合并（乐观锁）。
- `SB.archive.openImport()`；JSZip `loadAsync` 在本机读取 zip。
- Scene Runtime：无变化。

## 4. 架构 / 扩展契约变化

导出格式 `starbook-export` v1 正式成为导出 / 导入契约（`prompts/16-archive.md` 6.1）：`book.json.files` 原路径映射、`payload` 原样、每卷 `part.json`。`remap` 支持另一本书的备份（为未来多 Book 预留）。已写入 `docs/ARCHITECTURE_EXTENSION_CONTRACT.md`。

## 5. Auth / Membership / RLS 变化

无变化。导入使用编辑者现有的写入与上传权限。

## 6. 数据模型 / Migration 变化

无 schema 变化、无 SQL。导入写入现有 `book_data.payload` 字段（cities / memories / settings / trash）。

## 7. Storage / Media 变化

导入会把备份里**缺少的**文件上传到原路径（`upsert:false`，不覆盖已有文件）；其余无变化。

## 8. Git / Branch / PR / Merge 链路变化

无变化（`ship-starbook.ps1`）。

## 9. CI / Validation 变化

`tools/check_project.py` 新增 v1.12.1 检查：`importBackup`、`mediaExists`、导入对话框、`part.json`、`format` 校验存在。

## 10. GitHub Pages / Production Deploy 变化

## 17. Production 数据影响

- 是否需要重新导入旧数据？**否。**（导入是可选功能。）
- 是否需要运行 SQL？**否。**
- 是否会删除/覆盖现有数据？**默认否**；只有勾选「覆盖」时才用备份版本替换同 id 的回忆 / 城市（被替换的照片进入最近删除）。

## 18. 已知问题

- 手机导入大备份受内存限制，建议在电脑上导入。
- 导入的进度只统计上传的文件数，不显示字节进度。
- v1.12.0 导出的备份没有 `part.json`，导入时无法校验分卷是否属于同一次导出（其余校验照常）。

## 19. 回滚方案

revert v1.12.1 merge commit 即恢复 v1.12.0；已导入的数据保留（都是正常的回忆 / 城市 / 文件）。
