# Starbook v1.7.2 — 性能、照片加载与响应式比例优化

## 1. 版本目标

本版只做性能与响应式适配，不新增视觉主题、不重做特效设计。目标：

1. 消除页面切换时上一场景短暂滞留；
2. 降低 PC / 手机场景切换、城市目录、编辑器与放映卡顿；
3. 优化手机放映时照片加载速度与 Signed URL / 图片预取；
4. 优化城市编辑与更深层内容的画面、海报、照片卡片比例；
5. 保持 v1.7.1 的视觉语言与现有功能结构。

## 2. 用户可见变化

- 页面切换更快，`portal` 转场不再看到上一页残留在新页后方。
- 手机城市目录滚动时图片请求更少；缩影和离屏章节延迟加载。
- 点击放映前会提前准备前几张照片，弱网下等待次数减少。
- 手机城市章节海报从 16:9 调整为 3:2，极窄屏使用 4:3。
- 回忆编辑器手机端照片卡片更大；≤430px 变为单列 3:2。
- 桌面编辑器可用宽度更合理；手机放映厅海报尺寸和竖向空间更协调。

## 3. Runtime 链路变化

Runtime 主链不变：

`Auth → SB.user → SB.book.current → SB.store → Scene Runtime`

新增性能协作：
- `SB.perf` 增加 CPU / device memory 信息；
- `SB.nextPaint()` 供 scene swap 后等待浏览器完成 paint；
- `SB.fx.playback(on)` 让放映期间全局 Ambient FX 主动降帧；
- `SB.player.prime(memory)` 提前预热回忆前几张照片；
- `SB.store.prefetchUrls(paths)` 批量补 Signed URL。

## 4. 架构 / 扩展契约变化

无核心架构变化。

保持：
- `SB.book` = 数据 Book Context；
- `SB.magicBook` = 视觉魔法书；
- `SB.store` = Supabase Anniversary Bridge；
- Theme / Experience 边界不变。

性能 API 只属于前端运行时辅助，不改变未来多 Book / 多 Theme / Memory-first 扩展契约。

## 7. Storage / Media 变化

- 新增 `SB.store.prefetchUrls(paths)`，仅用于提前创建 / 刷新现有私有媒体 Signed URL。
- v1.7.2 以后新上传的唯一 Storage 对象使用 `cacheControl: 31536000`，提高浏览器 / CDN 重访缓存效率。
- 不修改旧对象，不搬迁已有照片，不改变 Private Bucket 与 RLS。
- 现有单一图片尺寸技术债仍存在；thumbnail / preview / full 多尺寸仍留到周年后。

## 9. CI / Validation 变化

- Player 必须暴露 `prime` 并通知 Ambient FX playback mode；
- Editor 必须保留 lazy 图片加载。

## 18. 已知问题

- 旧照片仍是单一压缩尺寸；首次打开时仍需要下载原 Storage JPG。
- Signed URL 为内存缓存，刷新页面仍会重新签名。
- `content-visibility` 优化主要由 Chromium 系浏览器受益；不支持的浏览器自动退化为普通布局。
- 弱网下首次放映仍可能 buffer，但预热窗口比 v1.7.1 更早。

## 19. 回滚方案

纯前端 / 新上传缓存元数据策略：
- revert v1.7.2 merge commit 即可回到 v1.7.1；
- 不回滚 Supabase；
- 不删除 Storage；
- 已上传对象的长 cacheControl 不影响权限与数据正确性。
