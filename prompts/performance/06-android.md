# 性能链路 06 · 安卓（v1.10.2）

> Owner（2026-10-29）：安卓手机兼容性不够好，转场不流畅，放映过程图片加载卡顿和闪烁。

## 1. 根因分析（依据 Chrome 渲染机制资料）
1. **大图解码与缩放在光栅阶段完成**：照片上传上限 2400px（约 2400×1800，解码后 ≈ 17MB 位图）；手机实际显示只需要 1000–1600px。安卓 Chrome 是多线程光栅，大图解码 / 缩放会卡住整条光栅队列，出现「卡顿 + 棋盘格（图片区域先空白再出现 = 闪烁）」。安卓 GPU 光栅不可用时 `decoding="async"` 会被强制同步；解码结果放在有限的解码缓存里，内存紧张时被逐出，再次显示要重新解码 → 再次闪。
2. **逐帧改变非合成属性**：放映器的「画内运动」逐帧改 `object-position`、照片位移时逐帧改 `width/height`（带大面积 `box-shadow`），每帧都要重新布局 / 重绘大图；只有 `transform / opacity` 由合成器直接处理。
3. **遮罩类转场**（百叶窗 `mask-image`、墨染 `mask-size`、光圈 `clip-path: circle`）由 JS 逐帧改写，每帧重绘整张照片。
4. **全屏 canvas 叠加**：氛围粒子两层全屏 canvas + 转场门 canvas，`lighter` 混合，在高像素密度安卓屏上纹理很大。
5. 地球徽章逐帧 `offsetWidth` 读写交错（强制同步布局）。

## 2. 方案
- **显示尺寸代理图**（`SB.store.displayUrl(id, side)`，只在安卓启用）：签名地址 → `fetch` 成 Blob → `createImageBitmap(blob, {resizeWidth/Height, resizeQuality})`（解码与缩放在浏览器后台线程完成）→ canvas 输出 JPEG（0.86）→ `blob:` 地址。长边 = clamp(屏幕长边 × min(dpr, 2), 1280, 1800)；卡片缩略图 480。原图不大于目标 1.15 倍时直接用原图。失败（跨域 / 内存）一律回退原地址。缓存最多 160 张，只回收当前页面没有在用的代理图；书本数据变化（文件删除）时回收对应代理。
- **放映器（low / 安卓）**：
  - 画内运动改为 `transform: translate() scale()`，`object-position` 只在进场时设一次；
  - 照片框尺寸在关键帧之间只是等比缩放时，用 `scale()` 代替逐帧改 `width/height`；
  - 安卓上百叶窗 / 墨染 / 光圈转场换成同节奏的淡入淡出 / 划入（其他设备不变）；
  - 预载的 `Image` 对象保留引用直到离开放映，减少解码结果被逐出。
- **时光剪影（安卓）**：使用代理图；剪影层改为预先算好的小尺寸灰度图（canvas 一次生成），不再对大图做 CSS 滤镜。
- **氛围层 / 转场门（安卓）**：粒子 canvas 像素比 1、数量 × 0.7；转场门 canvas 像素比 0.8（柔光元素，肉眼无差别）。
- **地球（安卓）**：渲染像素比上限 1；徽章尺寸缓存。

## 3. 验收
- 安卓 Chrome（中端机）：魔法书 → 地球 → 国家 → 城市 → 放映 → 返回，转场无明显掉帧；放映 30 张照片一轮不出现空白闪烁；时光剪影显影流畅。
- 桌面 / iOS：视觉与 v1.10.1 一致（代理图与转场替换只在安卓启用）。
